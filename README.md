# IoTRobotWorld: интерфейс, UDP и 2D-лидар

## Состав

- `main.py` — запуск приложения.
- `gui.py` — PyQt6-интерфейс, ручная отправка команды, таблица телеметрии и журнал.
- `udp.py` — UDP-приём в отдельном потоке и отправка JSON.
- `robot_data.py` — модели и разбор телеметрии.
- `robot.py` — модель робота и нумерация команд.
- `lidar.py` — отдельный UDP-приёмник и разбор кадров 2D-лидара.
- `lidar_view.py` — визуализация облака точек в координатах робота.

## Запуск

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
python main.py
```

## Настройка UDP

В окне приложения укажите:
- IP-адрес симулятора;
- порт симулятора, на который принимаются управляющие пакеты;
- локальный порт приложения, куда симулятор отправляет телеметрию.

Значения `127.0.0.1`, `7777` и `8888` — стартовые значения из каркаса, а не гарантированные настройки вашей установки. Их нужно сверить с окном подключения IoTRobotWorld. Симулятор и приложение на одном компьютере обычно используют `127.0.0.1`; на разных компьютерах нужно указать IP компьютера с симулятором и проверить правила брандмауэра.

## Формат пакета

Команда отправляется как JSON с переводом строки в конце:

```json
{"N":1,"M":0,"F":0,"B":0,"T":0}
```

`N` увеличивается для каждой команды. По QuickStart `M=0` — непосредственное непрерывное управление, а `F` — продольная тяга в диапазоне `-100..100`. В том же документе `B` описан как баланс тяги между моторами. При этом лабораторное задание для шасси ID=1 описывает управление скоростью и углом руля. Поэтому перед движением нужно проверить трактовку `B` именно в используемой версии симулятора. Для первого запуска оставьте `F=0`, `B=0` и проверьте только приём телеметрии.

## Лидар (2D)

1. В настройках IoTRobotWorld включите эмуляцию **2D-лидара** и укажите UDP-порт назначения. По QuickStart порт по умолчанию — `2368`, но он может быть изменён.
2. В интерфейсе нажмите **«Подключить лидар»** и укажите тот же порт в поле «Локальный UDP-порт».
3. Визуализация ожидает текстовый кадр формата `hh:mm:ss.nn> d0 d1 ...`; значения дальности — в миллиметрах, максимум 360 измерений на кадр.
4. Если облако повернуто относительно робота, измените «Угол смещения». По умолчанию нулевой угол рисуется вверх — вдоль передней оси робота.
5. «Макс. дальность» задаёт отображаемый радиус. Нулевые измерения и значения за пределами выбранного радиуса не рисуются.

Приём лидарных пакетов работает в отдельном потоке и не использует порт телеметрии/команд. Перерисовка ограничена примерно 5 кадрами в секунду.

### Лидар: единицы и ориентация

Симулятор присылает расстояния в миллиметрах. Парсер переводит их в миллиметры для визуализации. По умолчанию установлен поворот 180° для компенсации ориентации потока. Подписи расстояний убраны; сетка оставлена как визуальный ориентир.

### Отображение корпуса и масштаб

В визуализации нарисован корпус шасси ID=1 размером 60 × 90 см (ширина × длина), согласно QuickStart. Передняя часть ориентирована вверх. Начальная отображаемая дальность увеличена до 12 м; её можно изменить в интерфейсе.

## Маршрут CSV (текущая итерация)

Положите `CurrentRoute.txt` рядом с `main.py` — приложение загрузит его при запуске. Также маршрут можно выбрать кнопкой «Загрузить CSV…». Формат: по одной точке на строку, `X,Y` в метрах, например `1.25,2.50`. Пустые строки и строки, начинающиеся с `#`, игнорируются. Координаты должны соответствовать системе симулятора: X от западной границы, Y от южной.

GUI показывает таблицу точек и текущую цель. По телеметрическим координатам `long/latt` цель автоматически переключается при достижении расстояния 1,5 м; финальная точка помечается как завершение маршрута. На этом этапе реализованы загрузка/отображение маршрута и отслеживание цели, но автоматическое руление по маршруту и DWA ещё не включены.

В этой версии начальные порты переставлены местами относительно каркаса: порт симулятора `8888`, локальный порт телеметрии `7777`. Максимальная отображаемая дальность лидара по умолчанию — `4000 мм`; дальности сохраняются в миллиметрах.

## Автоматическое движение и DWA (итерация v2)

Кнопка «Автоматический режим» запускает локальный планировщик DWA с периодом 200 мс. Он генерирует кандидаты скорости и угла руления, прогнозирует короткие траектории и отбрасывает траектории, пересекающие точки лидара. Выбранная траектория рисуется зелёным цветом, текущая цель — синей меткой. Скорость ограничена настройкой формы (по умолчанию 0,20 м/с), а изменение скорости ограничено 0,20 м/с². Ненулевой `b` телеметрии приводит к аварийному останову.

**Важно перед первым автоматическим тестом:** в DWA `B` трактуется как руление (диапазон команды `-100..100` соответствует примерно `-30..+30°`), а `F` — как процент максимальной скорости. Это предположение основано на описании автомобильного шасси в задании и требует проверки именно в вашей сборке симулятора. Проверьте знак руления на минимальной скорости в свободном месте, держите руку у кнопки «СТОП». DWA использует локальные точки лидара с текущим угловым смещением; при отсутствии кадров лидара список препятствий пуст, поэтому перед автоматическим движением обязательно подключите лидар.
